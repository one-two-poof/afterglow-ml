# 장소 데이터 수집 및 선별 규칙

상태: 운영 기준 정리 중  
최종 검토일: 2026-08-29

## 문서 목적

이 문서는 강남구·서초구 장소 데이터를 수집하면서 확정한 규칙을 다른 자치구에도 동일하게 적용하기 위한 운영 기준이다.

핵심 목표는 다음과 같다.

- 카카오 장소 검색 결과의 지역별 누락을 줄인다.
- `categoryName`을 이용해 서비스용 `primaryType`과 `primaryTypeName`을 일관되게 만든다.
- 카테고리마다 다른 popularity 및 수동 검수 기준을 적용한다.
- 오탐, 중복, 서비스 부적합 장소가 최종 데이터에 들어가는 것을 막는다.
- 최종 CSV의 스키마와 정수 필드 형식을 유지한다.

## 대표 아이콘용 `primaryTypeName` 통합

고정 값 목록, `categoryName` 경로 매칭, 판정 우선순위와 미매핑 처리의 정규 명세는 [`PRIMARY_TYPE_MAPPING_RULES.md`](./PRIMARY_TYPE_MAPPING_RULES.md)를 따른다. 이 절과 내용이 다르면 정규 매핑 명세가 우선한다.

프론트엔드에서 대표 아이콘을 일관되게 표시하고 다른 출처의 데이터와 통합하기 위해 세부 명칭을 아래 표시용 대분류로 정규화한다. `primaryType`은 원래의 시스템 분류를 유지하므로, 같은 `primaryTypeName`이라도 내부 성격은 구분할 수 있다.

## 전체 수집 절차

### 1. 수집 대상 정의

수집을 시작하기 전에 다음 값을 확정한다.

- 대상 시·구
- 수집할 서비스 카테고리
- 카카오 카테고리 그룹 코드 또는 검색 키워드
- 허용할 `categoryName` 패턴
- 제외할 `categoryName` 및 상호명 패턴
- 결과의 `primaryType`, `primaryTypeName`
- popularity 적용 여부와 최소값
- 수동 검수 여부
- 기본 제약 필드 값

### 2. 격자 검색

구 이름을 붙인 키워드 검색 한 번으로는 결과 수 제한 때문에 누락이 발생한다. 대상 구를 덮는 격자를 만들고 각 좌표에서 반복 검색한다.

- 카페처럼 밀도가 높은 유형: 약 0.01도 간격을 시작점으로 사용
- 공원·문화공간처럼 밀도가 낮은 유형: 약 0.02도 간격을 시작점으로 사용
- 검색 반경과 격자 간격은 결과 포화 여부를 보고 조정
- 한 격자에서 API 최대 페이지까지 조회
- 새 장소가 거의 나오지 않을 때까지 경계 격자를 확인

위 간격은 강남·서초 수집에서 사용한 경험값이며 절대값이 아니다. 면적이 넓거나 형태가 긴 구는 경계 누락 검사를 별도로 수행한다.

### 3. 주소 필터

검색 중심점이 대상 구 안에 있어도 인접 구 결과가 함께 반환될 수 있다.

- `addressName`을 기준으로 대상 시·구와 정확히 일치하는 행만 유지한다.
- 장소명이나 검색어에 구 이름이 들어 있다는 이유로 채택하지 않는다.
- 도로명주소가 비어 있더라도 지번주소와 좌표가 정상이라면 바로 제외하지 않는다.

### 4. 중복 제거

- `kakaoPlaceId`를 유일 식별자로 사용한다.
- 여러 검색어 또는 여러 격자에서 발견된 동일 ID는 한 행만 유지한다.
- 장소명이 같아도 ID가 다르면 자동 병합하지 않고 실제 지점인지 확인한다.
- 최종 파일에서 중복 ID 수가 반드시 0이어야 한다.

### 5. 카테고리·오탐 필터

다음 순서로 판정한다.

1. 카카오 공식 카테고리 그룹 코드
2. 전체 `categoryName` 허용 규칙
3. 전체 `categoryName` 제외 규칙
4. 상호명 제외 규칙
5. 필요한 카테고리의 수동 검수

검색어에 일치했다는 이유만으로 채택하지 않는다. 검색어는 후보 수집 수단이고, 최종 업종 판정은 `categoryName`과 장소 상세 정보로 한다.

### 6. 세부 유형 매핑

- `primaryType`은 애플리케이션이 사용하는 영문 시스템 값이다.
- `primaryTypeName`은 사용자 목적 매핑에 사용하는 한글 세부 유형이다.
- 브랜드 단계가 붙은 카카오 카테고리도 일반 유형으로 정규화한다.

예:

- `문화,예술 > 영화,영상 > 영화관 > CGV` → `cultural_facility`, `영화관`
- `가정,생활 > 드럭스토어 > 올리브영` → `drugstore`, `드럭스토어`

### 7. Popularity 계산과 카테고리별 컷 적용

Popularity를 사용하는 유형만 계산한다. 모든 카테고리에 일괄 컷을 적용하지 않는다.

### 8. 수동 검수

Popularity는 인기도 보조 지표이며 업종 정확도나 서비스 적합성을 보장하지 않는다. 찜질·스파·마사지 및 모호한 복합공간은 반드시 상세 페이지를 확인한다.

### 9. 최종 검증 및 병합

아래 검증이 모두 통과한 파일만 실서비스 데이터에 병합한다.

- 컬럼 이름과 순서 일치
- 대상 구 이외 주소 0개
- 빈 `kakaoPlaceId` 0개
- 빈 좌표 0개
- 중복 `kakaoPlaceId` 0개
- `isNa=1` 0개
- 정수 필드에 정수만 존재
- 허용되지 않은 `primaryType`/`primaryTypeName` 조합 0개
- 카테고리별 popularity 및 수동 검수 조건 충족

## Popularity 규칙

### 계산식

현재 사용한 계산식은 다음과 같다.

```text
blogScore = min(5, log10(blogReviewCount + 1) * 2.5)

카카오 평점 리뷰가 있는 경우:
popularity = round(averageScore * 0.7 + blogScore * 0.3)

카카오 평점 리뷰가 없는 경우:
popularity = round(blogScore)
```

### 적용 기준

| 유형 | popularity 기준 | 추가 조건 |
|---|---:|---|
| 카페 | 5만 채택 | 명백한 오탐·폐점 검수 |
| 찜질방/사우나 | 4 이상 | 상세 페이지 수동 검수 필수 |
| 안마/스파 (`spa`) | 4 이상 | 상세 페이지 수동 검수 필수 |
| 안마/스파 (`massage_spot`) | 4 이상 | 상세 페이지 수동 검수 필수 |
| 문화시설 | 컷 없음 | 카테고리 정확성 우선 |
| 관광명소·공원 | 컷 없음 | 실제 방문·체류 가능성 우선 |
| 드럭스토어·백화점 | 계산 불필요 | 업종 및 지점 여부 우선 |
| 복합문화공간 | 참고값 | 엄격한 수동 검수 우선 |
| 서점·도서관 | 수집 제외 | 외국인 이용 난이도를 고려한 운영 결정 |
| 쇼핑몰 | 컷 없음 | 카테고리 정확성·시설 규모·체류 가능성 수동 검수 |

### 계산 실패 처리

- 리뷰 API 호출 실패를 popularity 0으로 처리하지 않는다.
- 실패 행은 재시도 대상으로 분리한다.
- 최종 후보에는 popularity 근거가 정상 수집된 행만 넣는다.
- 계산 시점과 원본 리뷰 수를 보고서 JSON 또는 별도 중간 산출물에 남긴다.

카카오 장소 웹 페이지에서 사용하는 리뷰 엔드포인트는 공식 Local API 계약과 별개일 수 있다. 응답 구조가 달라질 수 있으므로 매 수집 전에 소수 장소로 정상 작동 여부를 확인한다.

## 카테고리별 수집 규칙

### 카페

#### 수집

- 우선 카카오 카테고리 그룹 `CE7`을 사용한다.
- 기본값은 `primaryType=cafe`, `primaryTypeName=카페`이다.
- 음식점 카테고리 중 카페 이외의 일반 음식점은 수집하지 않는다.

허용 가능한 세부 유형:

- 카페
- 커피전문점
- 디저트카페
- 전통찻집
- 보드카페
- 갤러리카페

테마카페는 실제 체류형 카페인지 확인한다. 모임공간, 주점, 체험업체가 카페 검색에 섞이면 제외한다.

#### 선별

- 전체 후보에 popularity를 계산한다.
- `popularity=5`만 남긴다.
- 이후 폐점, 카페가 아닌 장소, 운영 실체가 불분명한 장소를 제거한다.

강남·서초 작업 근거:

- 수집 후보: 1,963개
- popularity 5 후보: 241개
- `isNa=1` 제거 후 현재 실서비스 채택: 209개

#### 제외 대상과 판단 근거

- 북카페·만화카페: 외국인 이용 난이도가 높아 제외한다.
- 애견카페·고양이카페: 피부 시술 이용자의 알레르기·자극 가능성을 고려해 제외한다.
- 키즈카페: 현재 주 이용자층과 맞지 않아 제외한다.
- 방탈출카페: 언어 의존도가 높아 외국인 이용이 어려우므로 제외한다.
- 보드게임카페: 외국어 안내나 외국인용 키오스크가 없는 소규모 매장은 수동 검수 후 제외한다. 일반 보드카페를 일괄 제외하지는 않는다.

### 찜질방·사우나·스파·마사지

#### 검색어

- 찜질방
- 사우나
- 목욕탕
- 스파
- 마사지
- 경락
- 안마
- 발관리
- 체형관리

#### 유형 및 제약 매핑

| 판정 유형 | primaryType | primaryTypeName | isHeatSource | isMassageSpot |
|---|---|---|---:|---:|
| 찜질방·사우나·목욕탕 | `heat_source` | 찜질방/사우나 | 1 | 0 |
| 마사지·경락·안마·발관리 | `massage_spot` | 안마/스파 | 0 | 1 |
| 열원과 마사지 서비스를 함께 제공하는 스파 | `spa` | 안마/스파 | 1 | 1 |

#### 제외

- 출장마사지
- 성인업소
- 장소가 없는 중개업체
- 숙박업소의 투숙객 전용 부대시설
- 단순 미용제품 판매점
- 마사지 서비스를 제공하지 않는 병원·의원
- 폐점 또는 운영 여부가 불명확한 장소

#### 선별

- popularity 4 이상만 1차 후보로 남긴다.
- 영업장 존재 여부와 실제 제공 서비스를 수동 확인한다.
- 상호명만으로 스파로 판단하지 않고 상세 카테고리와 소개를 함께 본다.

강남·서초 작업 근거:

- 수집 후보: 299개
- popularity 4 이상 후보: 95개
- `isNa=1` 제거 후 현재 채택: 마사지 48개, 스파 11개, 찜질방/사우나 7개

수동 검수에서는 규모가 지나치게 작거나 시설이 노후된 업소, 성인업소로 의심되는 업소를 제외한다.

### 드럭스토어

#### 허용

- `가정,생활 > 드럭스토어` 계열
- 올리브영 등 실제 드럭스토어의 정상 영업 지점

#### 제외

- 화장품 전문점
- 렌즈 판매점
- 피부관리실
- 법률사무소
- 일반 기업·관리업체
- 검색어와 상호 일부만 우연히 일치하는 업체

기존에 확인한 롭스앤그레이, 디벨롭스 계열, 화장품가게, 렌즈가게는 오탐으로 제외한다. 브랜드명만 허용 목록으로 관리하기보다 카카오의 전체 `categoryName`이 드럭스토어 계열인지 먼저 확인한다.

#### 선별

- popularity 컷을 적용하지 않는다.
- 실제 드럭스토어 지점인지 카테고리와 장소 상세 정보로 확인한다.
- 백화점 내부 매장도 별도 카카오 장소 ID와 정상 지점 정보가 있으면 유지할 수 있다.

#### 허용

#### 제외

- 주차장, 고객센터, 문화센터만 별도로 등록된 장소
- 면세점
- 아울렛의 단일 브랜드 점포

Popularity 컷은 적용하지 않는다.

### 문화시설

`categoryName`의 가장 구체적인 유효 시설 유형을 기준으로 분류한다.

| categoryName 신호 | primaryType | primaryTypeName |
|---|---|---|
| 미술관 | `cultural_facility` | 미술관 |
| 전시관, 전시시설 | `cultural_facility` | 미술관 |
| 공연장, 극장, 아트홀 | `cultural_facility` | 공연장 |
| 박물관 | `cultural_facility` | 박물관 |
| 영화관 및 영화관 브랜드 | `cultural_facility` | 영화관 |
| 문화원, 기념관 | `cultural_facility` | 문화원 |
| 아쿠아리움 | `cultural_facility` | 복합문화공간 |

Popularity가 낮다는 이유만으로 공공 문화시설을 제외하지 않는다. 리뷰가 적어도 실제 관람·체류가 가능한 시설이면 채택한다.

미술관·전시관·공연장은 강남·서초에서 수작업으로 선별했다. 향후 지역 확장 시 `popularity >= 3`을 1차 후보 기준으로 시험할 수 있으나, 아직 확정 규칙은 아니다. 표본 검증을 거쳐 공공시설이 과도하게 누락되지 않는지 확인한 뒤 채택한다.

## CSV 스키마 및 타입 규칙

컬럼을 추가하지 않고 아래 순서를 유지한다.

```text

kakaoPlaceId
isIndoor
isHeatSource
isMassageSpot
walkHard
isNa
primaryType
primaryTypeName
collectionTypes
skinTreatmentConfidence
skinTreatmentSignals
categoryName
categoryGroupCode
categoryGroupName
phone
addressName
roadAddressName

mapY
placeUrl
```

### 타입

- `isIndoor`: 정수
- `isHeatSource`: 정수
- `isMassageSpot`: 정수
- `walkHard`: 정수
- `isNa`: 정수
- `kakaoPlaceId`: 문자열 식별자
- `mapX`, `mapY`: 원본 정밀도를 보존하는 좌표 값
- 그 외 필드: 문자열 또는 빈 문자열

정수 필드는 CSV에서 `"1"`처럼 문자열로 감싸지 않고 `1`로 출력한다. `kakaoPlaceId`와 좌표는 값 변형을 막기 위해 수치 연산 대상으로 사용하지 않는다.

### isNa 규칙

- 중간 후보 파일에서는 검수 표식으로 사용할 수 있다.
- 실서비스 최종 파일에는 `isNa=0`인 행만 허용한다.
- `isNa=1` 행은 최종 병합 전에 모두 제거한다.
- 최종 검증에서 `isNa=1`이 한 행이라도 발견되면 병합 실패로 처리한다.

### walkHard 자동 산정 규칙

`walkHard`는 장소별 수작업 입력을 최소화하기 위해 위 유형별 기본값을 먼저 적용하고, `placeName`과 원본 `categoryName`의 명확한 신호로 덮어쓴다.

| 장소명·카테고리 신호 | 최종 walkHard |
|---|---:|
| 산, 등산, 봉, 고개, 능선 | 5 |
| 한강공원, 호수공원, 수변공원, 숲길 | 5 |
| 둘레길, 생태공원, 수목원 | 4 |

적용 우선순위는 `walkHard=5` 신호, `walkHard=4` 신호, 유형별 기본값 순이다. 예를 들어 `고난도 둘레길`이나 산·능선 신호가 함께 있는 둘레길은 5이고, 별도 고난도 신호가 없는 일반 둘레길은 4다.

- 대형 공원으로 수집·선별된 장소는 4를 적용한다.
- 일반 공원은 3을 적용한다.
- `primaryTypeName=자연`처럼 여러 원본 유형을 합친 값은 통합 명칭만으로 판정하지 않고 원본 `categoryName`과 장소명에서 산·숲 등의 신호를 확인한다.
- 신호가 중복되면 더 높은 값을 사용한다.
- 명확한 신호가 없으면 유형별 기본값을 유지하며, 임의 추정으로 값을 올리거나 내리지 않는다.

## 목적 매핑 연동 주의사항

`app/config/rule_config.yaml`의 목적 분류는 현재 `category_rule.purpose_keywords`를 사용하며, `primaryTypeName`과 원본 `categoryName`에서 키워드를 찾는다.

표시용 `primaryTypeName`을 통합했더라도 원본 `categoryName`에는 `전시관`, `기념관`, `스파`, `마사지`, `둘레길` 같은 세부 단어가 남을 수 있다. 목적 키워드는 다음 두 종류를 함께 관리한다.

1. 현재 표시용 명칭: `미술관`, `문화원`, `거리`, `자연`, `복합문화공간`, `안마/스파` 등
2. 원본 카카오 카테고리에서 발견되는 세부 명칭: `전시관`, `기념관`, `테마거리`, `스파`, `마사지` 등

새 통합 명칭을 추가하거나 변경할 때는 `purpose_keywords`도 함께 검토하고 추천 로직 테스트를 수행한다. CSV만 변경하면 목적별 후보가 누락될 수 있다.

## 권장 수집 규칙 설정 형태

향후 자동화를 위해 카테고리별 규칙을 다음 형태로 관리하는 것을 권장한다.

```yaml
categories:
  cafe:
    search_method: category_group
    category_group_codes: [CE7]
    search_queries: []
    category_allow_patterns:
      - "음식점 > 카페"
    category_deny_patterns: []
    name_deny_patterns: []
    primary_type: cafe
    primary_type_name: 카페
    popularity_min: 5
    manual_review: false
    default_constraints:
      isIndoor: 1
      isHeatSource: 0
      isMassageSpot: 0
      walkHard: 1
      isNa: 0

  heat_spa_massage:
    search_method: keyword
    search_queries:
      - 찜질방
      - 사우나
      - 목욕탕
      - 스파
      - 마사지
      - 경락
      - 안마
      - 발관리
      - 체형관리
    popularity_min: 4
    manual_review: true
```

실제 허용·제외 패턴은 코드에 흩어놓지 말고 설정 파일 한 곳에서 관리해야 다른 구에 동일한 규칙을 재현할 수 있다.

## 수집 실행 체크리스트

### 수집 전

- [ ] 대상 구의 경계와 격자 범위를 확인했다.
- [ ] 카테고리 그룹 코드와 검색어를 확정했다.
- [ ] 허용·제외 카테고리 패턴을 정의했다.
- [ ] 상호명 오탐 제외 목록을 최신화했다.
- [ ] popularity 기준과 수동 검수 여부를 정했다.
- [ ] 리뷰 수집 방식이 정상 작동하는지 표본 테스트했다.

### 수집 후

- [ ] 주소 기준으로 대상 구만 남겼다.
- [ ] `kakaoPlaceId` 중복을 제거했다.
- [ ] `categoryName` 허용·제외 규칙을 적용했다.
- [ ] `primaryType`과 `primaryTypeName`을 매핑했다.
- [ ] 필요한 유형에 popularity를 계산했다.
- [ ] 수동 검수 대상의 상세 페이지를 확인했다.
- [ ] 폐점·출장업체·개별 부대시설·상호명 오탐을 제거했다.

### 최종 병합 전

- [ ] 컬럼 이름과 순서가 기준 파일과 같다.
- [ ] 정수 필드가 문자열로 출력되지 않았다.
- [ ] `isNa=1`이 0개다.
- [ ] 대상 구 이외 주소가 0개다.
- [ ] 빈 ID와 빈 좌표가 0개다.
- [ ] 중복 `kakaoPlaceId`가 0개다.
- [ ] 목적 매핑 설정에서 새 `primaryTypeName`을 처리한다.
- [ ] 카테고리별 후보 수, 필터 후 수, 최종 채택 수를 기록했다.

## 운영상 결정 요약

- 검색어는 후보 발견용이며 최종 분류 근거가 아니다.
- 최종 분류는 `categoryName`, 장소 상세 정보, 수동 검수 결과를 함께 사용한다.
- 카페는 popularity 5만 사용한다.
- 찜질방·사우나와 `안마/스파`는 popularity 4 이상을 뽑고 직접 선별한다.
- 미술관·전시관·공연장의 popularity 3 기준은 검토안이며 아직 확정 규칙이 아니다.
- 그 밖의 문화시설과 공원은 리뷰가 적을 수 있으므로 popularity 일괄 컷을 적용하지 않는다.
- 음식점은 카페 외에는 수집하지 않는다.
- 최종 실서비스 파일에는 `isNa=1`을 허용하지 않는다.
- 신규 구 수집에서도 동일한 스키마와 매핑 규칙을 유지한다.
- 서점·도서관은 외국인 이용 난이도를 이유로 현재 수집 대상에서 제외한다.
- 쇼핑몰은 `가정,생활 > 상가,아케이드` 계열을 제외하고 시설 규모와 체류 가능성을 수동 검수한다.
- `복합쇼핑공간`과 `쇼핑몰`은 최종 `primaryTypeName=쇼핑몰`로 통합한다.
- 대표 아이콘용 `primaryTypeName` 통합과 원본 `categoryName` 기반 판정을 혼동하지 않는다.
